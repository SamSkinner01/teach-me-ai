## The network

Here is the network you'll train. Every layer is one you've built:

```text
layer                          output shape     learned numbers
input                          1 × 28 × 28
convolution, 8 filters 3×3     8 × 26 × 26      8·1·3·3 = 72 weights + 8 biases
ReLU                           8 × 26 × 26
2×2 max-pool                   8 × 13 × 13
flatten                        1,352
dense                          10               10·1,352 = 13,520 weights + 10 biases
softmax + cross-entropy        (the loss)
```

The convolution finds strokes and edges anywhere in the image, the pooling makes them a little less sensitive to exact position, and the dense layer weighs up the evidence for each digit.

That's a small network by today's standards, but it gets roughly 97–98% of the test digits right. A single dense layer on the raw pixels (multinomial logistic regression) levels off around 92%.

## Forward

For one image, with all tensors in the flat layout from Module 6:

1. `conv2d_multi` with the 8 filters gives $z$, shape $[8, 26, 26]$.
2. `relu` gives $a = \max(0, z)$.
3. Each of the 8 channels of $a$ is a $26 \times 26$ matrix: `maxpool2d` it with size 2 to get $13 \times 13$, then `flatten` it.
4. Concatenate the 8 pooled channels in order into one vector of 1,352 features.
5. `mat_vec(dense_w, flat)` plus `dense_b` (with `vec_add`) gives the 10 logits.

## Backward

Training needs the gradient of the loss for one image with respect to all 13,610 parameters. That's the chain rule run backwards through the same five steps, with every piece taken from your library:

```text
g       = cross_entropy_grad(logits, label)        10 numbers: softmax(logits) − one_hot(label)
dense:    d_dense_b = g
          d_dense_w[k][f] = g[k] · flat[f]          an outer product
          d_flat = dense_wᵀ · g                     mat_vec(transpose(dense_w), g): 1,352 numbers
unflatten d_flat into 8 slices of 13 × 13
per channel o:
          d_a   = maxpool2d_backward(a_o, slice o, 2)   each gradient goes to the max of its window
          d_z   = relu_backward(z_o, d_a)               zero wherever z ≤ 0
          d_conv_b[o] = sum of d_z
          d_conv_w[o, c] = conv2d_backward_kernel(image channel c, d_z)
```

One step you might expect is missing: the gradient with respect to the **image**. Nothing comes before the first layer, so nothing needs it, and you can skip the full convolution from the convolution-backprop lesson.

All the gradients go into one long vector, in a fixed order: the convolution weights, the convolution biases, the dense weights (row by row) and the dense biases. The training loop splits it back into parameters at positions 72, 80 and 13,600.

The reference solution's analytic and numerical gradients agree to about 10⁻¹⁰. A sign error or a mixed-up index shows up as an error near 1.

</Callout>

## How long one image takes

The convolution alone is $8 \times 26 \times 26 \times 9 = 48{,}672$ multiply-adds, the dense layer another 13,520, and the backward pass does a similar amount again.

<Lang only="python">

In plain Python, a forward and backward pass for one image takes about 15–20 ms. Rust or C++ do the same loops roughly 80 times faster. That's the price of an interpreter running every multiply-add one by one, and it's why libraries like NumPy and PyTorch hand these loops to compiled code. In the next lesson your Python network trains on 5,000 images, which takes about a minute and a half.

</Lang>
<Lang only={["rust", "cpp"]}>

Compiled to native code, a forward and backward pass for one image takes about 0.2 ms, so a full epoch over all 60,000 training images takes around 15 seconds on one CPU core. The same loops in plain Python would be about 80 times slower.

</Lang>

conv (8 × 3×3) → ReLU → 2×2 max-pool → flatten → dense (10). The backward pass runs the same steps in reverse, each using a backward function you've already written and checked, and produces one gradient vector of 13,610 numbers per image.

</KeyIdea>
